# Little Buddy — static character prototype

Original baby-dinosaur geometry based on the approved `ar-buddy-concept.html`.
This is a first-pass shape study, not a production-ready animated asset.

## Files

- `little_buddy.blend`: editable meshes, materials, studio lights, and camera.
- `little_buddy.glb`: self-contained glTF 2.0 model; no studio objects.
- `little_buddy.usdz`: self-contained USDZ model; no studio objects.
- `preview-front.png`, `preview-three-quarter.png`: renders of the actual model.
- `build-report.json`: model counts and dimensions.
- `verification.json`: export round-trip checks, not device certification.

Open `../../../ar-buddy-3d-preview.html` for the render comparison and downloads.

## Rebuild

Uses Blender 4.5.3 LTS. No purchased assets, downloaded meshes, fonts, or textures
are used. All geometry is generated by `tools/create_little_buddy.py`.

An isolated Python environment can run Blender without installing its GUI:

```sh
uv venv --python 3.11 .venv-buddy
uv pip install --python .venv-buddy/bin/python bpy==4.5.3
.venv-buddy/bin/python tools/create_little_buddy.py
.venv-buddy/bin/python tools/verify_little_buddy.py
```

Run from the repository root. Rebuilding overwrites this model's generated files.
The generator clears its active Blender scene, so use a separate Python process
or a new, unsaved Blender scene—not a scene containing other work.

## Scale and coordinates

- Meters; height 0.206 m, feet on Z = 0 in Blender.
- Blender source: Z up, front faces -Y.
- glTF export: Y up, front faces +Z.
- USDZ retains USD axis/unit metadata. Check orientation in the native loader.
- RealityKit applies the USDZ's Z-up correction on the loaded root. The reader
  wraps that root in an identity entity before measuring presentation bounds;
  measuring relative to the loaded root itself excludes the correction. Do not
  apply another -90° rotation. Native loader tests check Y-up height and feet.
- 32 mesh objects, 36,720 triangles, eight solid-color materials.
- No skeleton, animation clips, textures, audio, or runtime behavior.

## Verified

`tools/verify_little_buddy.py` checks GLB structure and embedded buffers, USDZ
uncompressed/aligned packaging, and re-imports both models into Blender. Both
formats have matching world-space bounds within 0.1 mm. Exported scenes contain
no cameras or lights.

## App integration

Little Buddy is the sole companion for scan and story entry, with no picker.
The GLB is bundled at `android/app/src/main/assets/little_buddy.glb` for every build;
the USDZ is registered in the iOS Runner resources. The existing Android debug
copy must stay identical to the main asset because debug assets take precedence.
After rebuilding the model, refresh both Android copies and the iOS bundle copy.
The character is still static; this integration does not add a rig or animations.

1. Review shape, colors, face, and material appearance on actual target phones.
2. Verify native loader scale and facing direction; Blender round-tripping does
   not establish ARCore/RealityKit compatibility or performance.
3. Merge/retopologize overlapping primitive meshes as needed for deformation.
4. Add a rig and idle, wave, and celebration clips; check platform animation support.
5. Reduce draw calls/geometry if necessary and test on lower-end devices.
6. Verify surface contact and tracking recovery on target devices before release.

The material values match the HTML palette approximately; studio rendering,
display color management, and real-world AR lighting affect the visible result.
