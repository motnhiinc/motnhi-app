Mọt Nhí · Storybook ARScreen wireframes — drawn from the code, not the spec

Toggles every frame through AppTheme.day() / AppTheme.bedtime()

Every frame below is reconstructed from the current working tree — routes from lib/core/router/app_router.dart, layout from each screen's build(), colour and type from StitchTokens, copy from lib/l10n/app_en.arb, and story content from assets/data/*.json. Frames are 375 pt wide, the same logical width the widgets lay out against, so spacing and type sizes are 1:1 with the Flutter values.

Long screens scroll inside their frame, exactly as the underlying ListView does.

00Route map & guards

Two redirects in goRouterProvider control everything: nothing is reachable until a consented profile exists, and any location under /parent bounces to /gate with the target in a redirect query parameter.

navigation passes through a guard returns / debug-only Orange node = the gate itself, deliberately outside /parent so guarding /parent* cannot trap it in a redirect loop. Not drawn: /home → /story/:id/read (Jump back in skips detail); /my-books → /story/:id/detail; /parent → /my-books and /story/:id/detail, with its back arrow re-locking the gate. /create-story is registered and builds, but nothing in the UI navigates to it — the composer's own doc comment ("reached from the library app bar") is stale.

01Entry & gates

Both screens are addressed to the grown-up. Onboarding is data-minimised by design — age band rather than birthdate, optional nickname, no photo, microphone off by default.

02Child surfaces

Everything a child touches: the home hub, their own shelf, the story preview, and the reader itself. The floating glass nav bar (Stories / My books / Moon mode) is present on the two shelf screens only.

03Reader overlays

Every one of these is presented over the player. The AR flow is deliberately three surfaces — pick, prepare, recover — because preparation takes seconds and must not leave the child on a dead screen.

04Parent surfaces

Both sit behind the gate. The dashboard is a gentle weekly summary rather than a performance report, and it is the only place a captured story can be deleted.

05Create & scan

Two related flows. Create a story ships in release builds and turns captured pages into a saved, authored story. Scan any page is a kDebugMode-only single-page demo that ends in the native AR character reader.

06Shared async states

Story detail, the player, the library grid, and the parent dashboard all resolve through the same two views, so a network hiccup looks identical wherever it happens.
